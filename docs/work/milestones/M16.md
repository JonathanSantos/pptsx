# M16 — Dívidas do motor e DX para agentes e devs

**Por quê:** de M6 a M15 o BOARD acumulou dívidas aceitas "para depois" e a experiência de uso ficou presa à CLI. Este marco paga as dívidas que afetam correção, e entrega os três canais que mudam como a engine é usada: um **servidor MCP** para agentes, um **preview ao vivo** para devs e um **lint com codemod** para migrar decks antigos. É o marco que prepara a 1.0.

**Execução:** sequencial, uma etapa por vez, pelo mesmo agente (ou pelo orquestrador); `typecheck` limpo, `npm test` verde, um commit `feat(m16-N): …` por etapa; notas em `docs/work/reports/M16.md`. Regras do `CLAUDE.md` valem.

**Pronto quando:** o BOARD não tem nenhuma linha de backlog aberta de M6 a M15 (ou cada uma restante tem decisão explícita "não fazer" com motivo); um agente conectado ao `pptsx-mcp` constrói, lê diagnósticos e vê o PNG de um deck sem usar o shell, e corrige um `broken.tsx` em ≤ 2 chamadas de `build`; `pptsx preview --serve` recarrega o browser em < 1 s após salvar; `pptsx lint --fix` migra `examples/agent-test/broken-original.tsx` (props antigas) para CSS sem mudar os frames (±1 pt); a suíte roda em CI em cada push.

## Etapas

### M16-1 — Dívidas de correção (sem API nova)
Cada item é um commit próprio com teste de regressão:
- **Baseline no Keynote com `lineHeight` numérico** (M11-G): só após a conferência do dono no PowerPoint. Se o PowerPoint fizer como o Keynote (1ª baseline em ≈ 0,8 × espaçamento), o emissor sobe a caixa de texto em `0,8·⌊lh⌋ − (ascent + meia-entrelinha)` e o preview acompanha; se o PowerPoint seguir o CSS, fica documentado como diferença do Keynote e nada muda.
- **Rotação herdada em Chart/Table** (M11-D): `css-not-emitted` também quando a rotação vem de um ancestral.
- **Loader com deck fora do cwd** (M9-E): `src/cli/loader.ts` compila com o `tsconfig.json` da pasta do deck (o mesmo que `assertDeckTsconfig` valida), caindo para o do cwd só se não existir.
- **`keynote-export.sh` com retry e trava** (M8-H): até 3 tentativas em -1712/-1700/-609 com 30 s, trava `mkdir` atômica em `/tmp/pptsx-keynote.lock` com pid, nunca espera arquivo de pausa de outra ferramenta.
- **`causedBy` entre linhas `auto` de grid** (M11-C, aceito como simplificado): tratar as linhas `auto` do grid como o wrap trata linhas; se o custo passar de ~150 linhas, registrar "não fazer".
- **`image-size` via pptxgenjs** (`npm audit`, M7-G): `overrides` no `package.json` para a versão corrigida, com `test:package` verde.
- **Watch com memória crescente** (M7-B): medir 200 rebuilds; se crescer > 50 MB, reciclar o registro de fontes e o `namespace` do tsx a cada N builds.

### M16-2 — Uma visão só do nó (`css` sem `props` derivados)
- Hoje `ResolvedNode` carrega `css` (fonte) e `props` (visão da engine derivada, M11 decisão 5). Esta etapa faz `layout`, `fit`, `emit` e `preview` lerem `css` e as props não-CSS (`fit`, `minSize`, `maxLines`, `src`, `data`, `columns`, `rows`, `kind`, `paginate`, `href`, `id`…) diretamente; `legacy.ts` e os helpers `containerOf`/`textStyleOf`/`edgesOf` sobre `props` saem; `defaults.ts` passa a derivar de `css`.
- Garantia: fixtures de paridade (`engine-positioned.json`, `css-positioned.json`, `poc-slides.json`) e calibração não mudam **nada**. Commit único grande, revisado pelo diff das fixtures.
- Testes: os helpers de `tests/helpers/nodes.ts` passam a montar só `css`; `tests/resolve/aliases.test.tsx` continua garantindo os aliases.

### M16-3 — Servidor MCP (`packages/mcp` ou `src/mcp/`)
- Binário `pptsx-mcp` (stdio) com as ferramentas: `build({ deck, sizes?, debug?, lineBreaks? })` → `{ files, diagnostics, fontsMissing, previews: [{ size, slide, pngBase64 }], overview }`; `diagnose({ deck, sizes? })` → só diagnósticos (rápido, sem preview); `preview({ deck, size, slide })` → um PNG; `init({ dir })`; `guide({ section? })` → trechos do `AGENT_GUIDE.md` por seção; `schema()` → JSON Schema das props por primitiva (gerado dos tipos em build).
- Resultado com `isError` quando há `error`; mensagens de diagnóstico inalteradas (já são para LLM).
- Empacotamento: `exports['./mcp']` e `bin.pptsx-mcp`; o SDK MCP em `dependencies` **opcionais** (`optionalDependencies`) para não pesar a CLI; README com a configuração para Claude Code/Desktop e Cursor.
- Testes: cliente MCP de teste chama `build` num deck com erro e recebe `isError` + diagnósticos; `preview` devolve PNG válido; `guide('§8')` devolve a seção.
- **Pronto quando:** um agente virgem, só com o servidor conectado e sem shell, corrige `examples/agent-test/broken-original.tsx` em ≤ 2 `build`s.

### M16-4 — Preview ao vivo (`pptsx preview --serve`)
- Servidor HTTP local (sem framework, `node:http`) que serve uma página com os SVGs dos slides (o mesmo `slideToSvg`, sem rasterizar) e os diagnósticos ao lado; `--watch` interno recompila ao salvar e empurra por SSE; seletor de tamanho (16x9/4x3/wide) e botão `--debug`; clique num diagnóstico destaca o nó pelo path no SVG.
- Sem estado no servidor além do último resultado; nada de bundler: a página é um HTML estático em `src/cli/preview/`.
- Testes: servidor responde `/`, `/svg/16x9/1`, `/diagnostics.json`; SSE emite após um rebuild (watch injetado como no M7).
- **Pronto quando:** salvar o deck atualiza o browser em < 1 s e o destaque por path funciona.

### M16-5 — `pptsx lint` e codemod
- `pptsx lint <deck>`: carrega o deck, resolve e reporta (sem build): props antigas (aliases) com a troca sugerida, `style` com propriedades sem de/para, cores fora do tema (se houver tema, M15), `lineHeight` numérico ≥ 1.5 (aviso do Keynote), `1fr` em grid de cartões com valores, `Chart` sem tamanho. Saída texto e `--json`.
- `pptsx lint --fix`: codemod por AST (`ts-morph` em `devDependencies`? não: `typescript` já está; usar o `ts.transform`) que reescreve aliases para CSS (`direction="row"` → `display="flex"`, `fill` → `backgroundColor`, `size` em Text → `fontSize`, …), preservando formatação com `ts.createPrinter` + diff mínimo; nunca toca em componentes (`size` de `Bullets` não é alias).
- Testes: cada alias; arquivo com componentes não muda; `--fix` em `broken-original.tsx` mantém frames (±1 pt) comparando antes/depois.
- **Pronto quando:** `examples/agent-test/broken-original.tsx` migrado por `--fix` gera a mesma árvore.

### M16-6 — CI, empacotamento e caminho para a 1.0
- GitHub Actions: `typecheck`, `test`, `build`, `test:package` (com cache do npm), lint do próprio repo (tsc `--noUnusedLocals`), geração de PNGs da galeria como artefato.
- `CHANGELOG.md` a partir dos commits de gate (M6–M16); política: aliases antigos removidos na 1.0 (lint avisa desde já); `exports` revisados; `npm pack --dry-run` auditado (sem `docs/readme`, sem exemplos pesados).
- README: seções "MCP", "Preview ao vivo", "Migração"; `docs/AGENT_GUIDE.md` §7 com o MCP como caminho preferido para agentes.
- **Gate:** BOARD limpo, ROADMAP, versão 0.6.0 (candidata a 1.0 após a validação do dono no PowerPoint).

## Fora deste marco
Extensão de VS Code (o preview ao vivo cobre 80 %); importar `.pptx`; API de plugins; modo office/LibreOffice (decisão do M3).

## Riscos
- **M16-2 é um refactor grande** sem feature: só vale com as fixtures de paridade como rede; se o diff de fixtures não for zero, parar e investigar antes de seguir.
- **MCP** depende de o agente hospedeiro aceitar imagens no resultado; manter `preview` separado de `build` para quem não aceita.
- **Codemod** sobre TSX com JSX spread e props computadas: reescrever só o que é literal; o resto vira aviso do lint.
