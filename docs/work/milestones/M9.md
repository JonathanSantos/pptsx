## Contrato (M9-0)

> **Fonte da verdade: `docs/work/CONTRACTS.md` §M9** e `src/core/{types,defaults,responsive}.ts`. O texto abaixo é o rascunho original; onde divergir, vale o CONTRACTS. Diferenças decididas no M9-0: `paginate` fica em `BoxProps` (não em `ContainerProps`: Slide não pagina); a regra de precedência mora em `src/core/responsive.ts` (`pickResponsive`), usada por `ctx.pick` e pelo resolve; `ResolvedSlide.sourceSlide` carrega o índice do autor; `fitDeck` recebe `{ deck, size, env }`; os Text dentro do Box paginate não encolhem em nenhuma tentativa enquanto o slide pagina (só no caso "nada cabe").

### Valores responsivos

```ts
/** Breakpoints nomeados: derivados de ctx, ou o nome exato do tamanho. */
export type Breakpoint = 'tall' | 'wide' | SizePresetName | (string & {});
export type Responsive<T> = T | ({ readonly base: T } & Partial<Record<Breakpoint, T>>);
```

- `tall` ⇔ `ctx.aspect < DEFAULTS.breakpoints.tallAspect` (1.5); `wide` ⇔ `ctx.scale > DEFAULTS.breakpoints.wideScale` (1.2). Nome de tamanho ⇔ `ctx.name` (inclui `custom-10x7.5`).
- Precedência: nome exato do tamanho > `wide` > `tall` > `base`. (Um `wide` 4:3 custom poderia ser `tall` e `wide`; `wide` vence porque mexe em tipografia, `tall` em estrutura; documentar.)
- Um valor é responsivo **se e só se** é um objeto com a chave `base`. Isso o distingue de `padding: { top, ... }` e `background: { image }`. `base` é obrigatória.
- Onde vale: **toda** prop de `FlexItemProps`, `ContainerProps`, `StrokeProps`, `TextStyleProps`, `fit`, `minSize`, `maxLines`, `radius`, `background`, `fit` de Image, `paginate`. Não vale em `children`, `src`, `kind`, `notes`. Os tipos das props passam a ser `Responsive<X>` (via um tipo utilitário `ResponsiveProps<P, Exclude>` em `types.ts`, para não reescrever cada interface à mão).
- Resolução acontece no **resolve** (`resolveDeck(root, ctx)`): a árvore resolvida só tem valores concretos; layout, fit, emit e preview não mudam. `ResolvedNode.props` fica com os tipos atuais (não responsivos).
- Componentes de usuário podem repassar valores responsivos sem resolver (`<Bullets size={{ base: 20, wide: 24 }} />` → `<Text size={size}>`).
- `ctx.pick(value)` em `DeckContext`: resolve um `Responsive<T>` em código (para contagem de itens, textos alternativos etc.). Mesma regra de precedência.

Exemplo (demo):
```tsx
<Bullets size={{ base: font.h2, tall: font.h2 + 4, wide: font.h2 + 6 }} gap={{ base: space.gap * 0.8, tall: space.gap * 1.25, wide: space.gap * 1.25 }} … />
<TwoColumn direction={{ base: 'row', tall: 'column' }} ratio={0.45} left={…} right={…} />
<KpiRow size={{ base: 'md', tall: 'lg', wide: 'lg' }} … />
```

### Slide de continuação

```ts
export interface ContainerProps { /* ... */
  /**
   * Box cujos filhos em fluxo, quando não cabem, continuam num slide clonado.
   * Só um Box paginate por slide. Padrão false.
   */
  readonly paginate?: boolean;
}
export type DiagnosticCode = /* ... */ | 'slide-continued';
export interface Diagnostic { /* ... */ readonly data?: { /* ... */ readonly sourceSlide?: number; readonly parts?: number } }
```

Regras (fit no nível do deck, `fitDeck(deck, size, env): { positioned, diagnostics }`):
1. Para cada slide com um `Box paginate` (mais de um → `ResolveError` no resolve), o fit roda primeiro **sem shrink nos Text dentro do Box paginate** (eles ficam fora dos escopos). Se não há estouro dentro do Box nem `box-overflow` nele, segue normal.
2. Se há: bisseção no número `k` de filhos em fluxo do Box (`1..n`) procurando o maior `k` em que o slide com só os `k` primeiros filhos **não** tem estouro no Box. Cada tentativa é um `fitSlide` completo (os demais textos do slide podem encolher normalmente).
3. Slide `i` sai com os `k` filhos. Um clone do slide (mesmas props, mesmos outros nós, mesmo path de slide) recebe os filhos `k+1..n` no Box; repete a partir do passo 2 com o clone. Filhos `position="absolute"` do Box vão em todos os clones.
4. Se `k` seria 0 (nem o 1º filho cabe), o slide fica inteiro e os diagnósticos normais aparecem (o shrink volta a valer para o Box nesse caso).
5. Índices: `Diagnostic.slide` é o índice no deck **de saída**; `data.sourceSlide` é o índice do slide no `<Deck>` do autor. Cada slide gerado por paginação (inclusive o primeiro) recebe `slide-continued` (info) com `data.parts` = total de partes e mensagem `"Slide 2 do autor virou 3 slides (3 de 12 itens no 1º, 5 no 2º, 4 no 3º)..."` — só no primeiro.
6. `notes` do slide vão em todas as partes. Preview e overview numeram pelo deck de saída.
7. Limite: `DEFAULTS.paginate.maxParts` = 10; passou → `box-overflow` no Box com mensagem dizendo que a paginação parou.
8. `render.ts` troca o `fitDeck` interno pelo exportado de `src/fit/`.
