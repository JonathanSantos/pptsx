# M19 — Composição: responsivo por contêiner (proposta)

**Status:** M19-1 a M19-3 feitos (sem mudar `src/core`); **M19-4 aprovado pelo dono e implementado** (contrato em
`CONTRACTS.md` "### `Container` (M19-4)"; `src/containers.ts`; ds-orbit migrado). Os 98 PPTX de exemplo do repositório
saem idênticos byte a byte ao commit anterior (só os GUIDs aleatórios de seção do pptxgenjs variam, como entre duas
execuções iguais).

**Por quê:** um DS grande (Vivo Orbit, 42 componentes + 8 layouts, em `packages/ds-orbit`, local) mostrou que o
pptsx compõe bem um componente por slide, mas não dois ou três lado a lado: o responsivo do núcleo
(`{ base, tall, wide, … }`) é **do slide**, então um componente numa meia coluna não sabe que está numa meia coluna.
No teste de composição (8 slides com 2–3 componentes) todos quebraram (24 estouros). O DS contornou com uma prop
manual `size: 'full' | 'narrow' | 'short' | 'small'` que as peças `Split`/`Rows`/`Grid` injetam nos filhos; funciona
(o mesmo deck saiu sem diagnóstico), mas só porque o DS controla as peças de fora. Um `Box` qualquer em volta do
componente, uma proporção diferente ou um aninhamento novo quebram a conta. O lugar certo é o núcleo: **o componente
receber o tamanho real do espaço que tem.**

## Feito (sem mudança de contrato de tipos)

### M19-1 — Contribuição mínima do item de grid respeita `minWidth` ✅
- `src/layout/grid-layout.ts` (`minContributionOf`): com `minWidth` numérico e `width` não numérica, a contribuição
  mínima do item é o `minWidth` (CSS Grid §11.5/§6.6). Antes, `minWidth={0}` era ignorado e a trilha `1fr` crescia
  até o min-content (uma linha `nowrap` comprida espremia as outras colunas).
- Contrato: `CONTRACTS.md`, layout, "Contribuição mínima do item de grid (M19)".

### M19-2 — `aspectRatio` + `maxHeight` num item esticado pelo grid ✅
- `src/layout/grid-layout.ts` (`transferredMaxWidthOf`): o grid estica o item na largura (grow), e isso vencia a
  proporção: uma forma redonda numa célula 240 × 150 saía 240 × 150. Agora `maxWidth = min(maxWidth, maxHeight ×
  aspectRatio)` (restrição transferida, CSS Sizing 4 §5.1) → 150 × 150. As outras 6 variantes testadas (coluna, linha,
  flex 1, célula com Box intermediário, stretch no eixo cruzado) já estavam certas.

### M19-3 — Ids de conector com escopo de componente ✅
- `src/resolve/connector.ts` (`scopeIds`): o mesmo id pode se repetir em **instâncias diferentes** de componente; cada
  conector se liga à ocorrência do seu escopo, subindo para os de fora; empate → `ResolveError` "ambíguo"; repetido no
  mesmo escopo continua erro. Ids únicos saem como antes. Antes, repetir um componente com conectores (um `Flow` numa
  grade) abortava o build inteiro.

### Investigado e não reproduzido
- "`display: none` responsivo ainda conta na largura mínima da grade": o resolve remove nós escondidos antes do
  layout (`resolve.ts`, `isDisplayed`); nenhum caso reproduziu. O sintoma no DS era a lacuna do M19-1.

## M19-4 — `Container`: o componente recebe o tamanho do seu espaço ✅

### API

```tsx
import { Container } from 'pptsx';

// O filho é uma função do espaço medido (content box do Container, em pt).
<Container flex={1}>
  {(box) => (box.width < 420 ? <KpiCompact {...props} /> : <KpiFull {...props} />)}
</Container>

// Atalho para valores: as chaves de contêiner valem dentro da função, como ctx.pick para o slide.
<Container>{(box) => <Text fontSize={box.pick({ base: 20, narrow: 14 })}>…</Text>}</Container>
```

```ts
interface ContainerBox {
  readonly width: Pt;           // content box medido
  readonly height: Pt;
  readonly aspect: number;      // width / height
  readonly narrow: boolean;     // width < DEFAULTS.container.narrow (padrão 480 pt)
  readonly short: boolean;      // height < DEFAULTS.container.short (padrão 240 pt)
  readonly pick: <T>(value: ContainerResponsive<T>) => T;  // narrow/short/small > base
  readonly slide: DeckContext;  // o contexto do slide, para combinar com tall/wide
}
type ContainerResponsive<T> = T | { readonly base: T; readonly narrow?: T; readonly short?: T; readonly small?: T };
interface ContainerProps extends FlexItemProps, ContainerStyleProps {
  readonly children: (box: ContainerBox) => Child;
}
```

### Semântica
- **Contenção de tamanho** (como `contain: size` do CSS): o tamanho do `Container` vem do pai e das props dele
  (flex, width/height, grid), **nunca do conteúdo**. É isso que torna a medição determinística: o conteúdo escolhido
  pela função não muda o espaço que ela recebeu. Num pai que depende do conteúdo (coluna sem altura), o `Container`
  tem altura 0 → diagnóstico `container-unsized` (warning) com a dica de dar `flex`/`height`.
- **Duas passadas, só nos slides que têm `Container`:** (1) resolve com cada `Container` vazio + layout → frames dos
  contêineres por path; (2) chama cada função com o seu `ContainerBox`, resolve e faz o layout de novo; depois o fit
  como hoje (o fit não muda o tamanho do contêiner, porque ele não depende do conteúdo). Aninhados: uma passada a mais
  por nível, até `DEFAULTS.container.maxDepth` (padrão 3); acima disso, `container-depth` (error).
- **Path:** `… > Container > …` (o `Container` é um nó de layout, como um `Box` sem pintura), então diagnósticos e
  lint continuam apontando o lugar certo.
- **Paginação:** `Container` dentro de um nó `paginate` → `ResolveError` nesta versão (o tamanho de cada parte só
  existe depois da paginação).
- **Slides sem `Container`:** caminho de hoje, sem passada extra (custo zero).

### Como ficou (diferenças em relação à proposta)
- Nomes: `ContainerQueryProps` (já existia `ContainerProps` para o contêiner flex) e `DEFAULTS.containerQuery` (já
  existia `DEFAULTS.container`). `ContainerBox.slide` é o contexto do slide recebido pelo deck.
- O Container vira `ResolvedBox` com `container: 'pending' | 'measured'`; com medida, fixa width/height no frame
  medido e zera grow/shrink (contenção). `resolveMeasured` (interno) faz as regras externas do lint verem o conteúdo.
- ds-orbit: `Split`/`Rows`/`Grid` medem cada espaço com `Container` e derivam o `size` do tamanho real
  (`SIZE_LIMITS { narrow: 560, short: 260 }` do DS); peça nova `Fit` para um componente em qualquer `Box`.
  `compose.tsx` (9 slides, inclusive `Box width="37%"` + `Fit`) e as matrizes saem sem diagnóstico.
- Não feito: medir automaticamente todo componente sem `Fit` (mudaria todos os slides de corpo inteiro: fica opt-in).

### O que muda no ds-orbit (e em qualquer DS)
- `Split`/`Rows`/`Grid` passam a envolver cada filho num `Container` e a derivar o `size` do tamanho medido, não da
  fração (`narrow` = largura < 480 pt etc.). Um `Box` qualquer em volta do componente, proporções livres e
  aninhamento passam a funcionar sem conta manual.
- Componentes podem ler o espaço direto (`<Container>{(box) => …}</Container>` dentro do próprio componente) e a
  prop `size` vira opcional (override).

### Alternativas descartadas
- **Chaves de contêiner nas props (`{ base, '@narrow': … }`)**, resolvidas depois do layout: mudam só estilo, não a
  estrutura (o componente compacto costuma ter outra árvore), e exigem re-resolver tudo do mesmo jeito.
- **Todo componente recebe `ctx.box` automaticamente** (`Component(props, ctx)`): mudaria a assinatura de
  `Component` e a expansão de todos os componentes, com 2 passadas em todo slide. O `Container` é opt-in e localizado.
